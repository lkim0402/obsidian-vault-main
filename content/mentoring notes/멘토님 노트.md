### 1. 구조 개선 & 리팩토링
- **Clean Code & SOLID 원칙**: 단순히 동작하는 코드가 아니라 유지보수성과 확장성을 고려한 설계 능력이 중요.
- 디자인 패턴 적용 경험: 전략 패턴, 상태 패턴, 템플릿 메서드, 정책 패턴 등 → 실제로 프로젝트 코드에 적용해보고 장단점 정리.
- 테스트 코드 작성: 단위/통합 테스트, TDD 사이클 경험. **Mockito, Testcontainers** 등을 활용한 학습.
### 2. 배치 활용
- **Spring Batch 기본기**: Chunk 기반 처리, Reader/Processor/Writer 구조 이해.
- 실무 시나리오: 대용량 데이터 ETL, 통계 집계, 로그 수집/분석 같은 배치 시나리오 직접 만들어보기.
- **스케줄링**: 단순 cron → **Airflow/Jenkins** 등과 연동하여 운영 환경에 가까운 배치 파이프라인 설계 경험.
- 장애 대응 전략: 실패 시 재시도, **skip/retry 처리**, DLQ 연동 같은 운영 안정성까지 고려.
### 3. 인증/인가 (Spring Security)
- **JWT 인증 플로우**: 로그인 → 토큰 발급 → 필터/인터셉터 → 토큰 검증.
- 권한(Role) 기반 인가: USER, ADMIN 등 권한별 접근 제어.
- **OAuth2/Social Login**: 구글, 카카오 로그인 연동도 경험해두면 강점.
- 테스트: 인증이 적용된 API에 대해 **MockMvc나 RestAssured**로 테스트하기.
### 4. MSA & 비동기 메시징
- 서비스 분리 연습: 단순 모놀리식 서비스에서 주문/결제/알림 등을 분리해보기
	- ***실제 서비스 2개 이상 만들어봐서 서로 통신하게 해보기!***
	- A와 B 분리 ->
		- A에서 B를 호출할때 API콜만 쓰는게 아니라 kafka나 다른 툴을 사용할 수 있음 (event stream, 비동기로 분류 -> 의존성 약화 전파)
		- 나중에 리팩토링 단계에서 도메인을 나누기, API콜을 할 필요가 없으면 event stream으로 데이터를 처리하도록 만들어본다
- **Kafka / RabbitMQ**: 이벤트 발행-구독 모델 직접 구현해보기.
- 데이터 일관성: **SAGA 패턴, Outbox 패턴** 등 트랜잭션 처리 전략 고민.
- 분산 환경 이슈: 장애 전파 차단을 위한 **Idempotent 처리** 학습.
### 5. Redis 활용
- 캐싱 전략: 자주 호출되는 조회 API에 캐싱 적용.
	- 실제 API에 적용하는건 어렵지 않음
- TTL과 갱신 정책: 캐시 무효화 시점 설계.
- 분산락(Lock): 동시성 문제 해결을 위한 분산 락 같은 시나리오에 적용.
	- *shared lock 만들어서 적용*
- *캐시랑 분산락 만들어보기*
- 세션 스토리지: 로그인 세션 관리 실습.
