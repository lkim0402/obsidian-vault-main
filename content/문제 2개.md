# 1000개 서버 감염 찾는 문제
- 문제
	- 1000개의 서버가 있고 10개의 클라이언트가 있다. 이중 1개의 서버는 감영된 상태이다. 각 클라는 모든 서버에 요청을 보낼 수 있고 클라가 감염되면 5분 이후에 확인할 수 있다. 5분 후에 감염된 서버를 찾아내는 방법은? (요청을 보내는 시간을 0초라 가정한다.)
- 답안
	- 먼저 생각한 방식
		- 먼저, 클라 -> 서버 매핑을 사용하면 된다.. 하지만 클라 1 -> 서버 1~10으로 해도 어느 서버 "그룹"에 감염 서버가 있을지는 알아낼 수 있지만, 하나의 서버를 딱 골라서 알아낼 수는 없다
		- 클라이언트랑 서버를 더 잘 매칭시킬 수 있을까? 서버를 *다른 방식*으로 표현할 수 있을까?
	- 이진법 (binary)를 사용하면 된다
		- 1000번째 서버는 $2^{10}$이고, 이진법을 사용하면 10 개의 자릿수가 생긴다.
		- 1000개의 서버에 각각 1부터 숫자를 붙힌다. 
		- 5 분 후에, 감염된 크라이언트들을 알수 있다. 그러면 이 크라이언트들의 이진법을 더하면 감염된 서버의 이진법이 나온다.

# `finda` 면접 문제
>[!note]
>백엔드/데이터 파이프라인에서 1,000개의 뉴스 데이터를 10-15개로 어떻게 추려내지? Naver API등 다양한 API를 사용해서 가져옴.
>- 면접 의도 -> 문제 해결, 커뮤니케이션

- 시도
	- 일단 모든 데이터를 llm에게 던져주면 문제는 hallucination, 비용이 올라가서, 이거를 어떻게 효율적으로 해야할지 생각해야했었음. 모르겠어서 면접관님이 chunking + embedding화하기  말씀해주심 (<< 이거를 기억 못했었음;; ㅜㅜ). 
	- 반복되는 뉴스 데이터 없애기....
	- 진짜 어떻게 붙었는지 모르겠엄..
- gemini 왈 답
	1. 데이터 수집, 정규화
		- 다양한 API에서 가져오면 일관된 json 구조가 다 다름. 
		- 인터페이스를 설계해서 각 api의 데이터를 일관된 스키마로 변환
	2. 필터링/중복제거
		- 모든 텍스트 분석하는 것은 리소스 낭비
		- **1차 -> 하드 필터링**
			- 반복되는 url이나 동일한 제목은 즉시 제고
	3. 텍스트 임베딩 (chunking, embedding)
		- 컴퓨터 뉴스 내용의 의미를 이해하고 비슷한 기사끼리 묶으려면 텍스트를 숫자/벡터로 변환해야함
		- **청킹** -> 의미 단위 (문단 등)으로 텍스트 쪼개기
		- **임베딩** -> 청킹된 텍스트를 벡터 공간의 좌표로 변환
	4. 클러스터링
		- 임데빙된 벡터들을 기반으로 의미가 비슷한 기사들을 그룹화
			- k-means, dbscan 같은 클러스터링 알고리즘
			- 클러스터의 크기가 크다는 것은 여러 언론사에서 다투어 보도하고 있다는 뜻 (트렌딩한 이슈)
	5. 중요도/랭킹
		- 생성된 여러 클러스터 중, 어떤 것이 가장 중요한지 점수 매기기
		- 클러스터 크키, 최신성, 신뢰도 등
	6. 최종 추출/요약
		1. 가장 점수가 높은 상위 10-15개의 클러스터 선택, 각 클러스터에서 대표 기사를 하나 뽑거나 LLM을 사용해 클러스터 . 내기사들을 1-2줄로 요약
